# ADR-002 可信任的 PR 交付管線

狀態為 Accepted（推薦方向）。負責人核准 hosted Windows CI、main Ruleset 與獨立最小權限身分方向。Reviewer App 實際安裝、可計入核准能力與憑證隔離尚待驗證。

## 已確認現況

GitHub Repository 為 Public，預設分支 main 未受保護，公開 ruleset 與 main active rules 查詢均為空清單。GitHub Actions 已啟用，允許所有 Actions，未強制固定 SHA，工作流程數為零。現有 Git Credential Manager 身分有 admin 與 push 權；這對建立工作分支有效，但不足以隔離日常 Agent 與管理權。未修改 GitHub 設定。

Codex CLI 使用 ChatGPT 認證。ADK-001 獨立唯讀 Session 的 PowerShell 和 cmd.exe 呼叫遭外層執行政策拒絕。Root cause 目前定位到該 Windows 執行邊界；具體拒絕規則未驗證。應驗證以獨立的正式來源唯讀 checkout 及專用暫存寫入根目錄啟動 Reviewer，保留既有 Sandbox。GitHub 身分另行隔離。

本機驗證 gate 將 Git for Windows 程式路徑及雜湊綁定於當前安裝，也校驗 Gitleaks 的 Windows x64 執行檔。Hosted runner 映像與本機不同，須實測。可重播的 ADK-001 Eval 基線是單一 Program 案例與單一 Reviewer 故障探針。

## 推薦

1. 使用 GitHub-hosted Windows CI。CI 讀取精確 PR 合併候選，工作權限限 contents read，無專案 secrets；禁止使用 PR 提供的內容取得提高權限。固定工程工具及下載雜湊，先證明發布來源、Runner 相容性與 Git 執行檔驗證等效，再讓 CI 執行現有 gate。若需 Actions，固定上游 commit SHA。掃描 PR 的精確提交範圍並記錄 run ID、base、head 與 merge candidate SHA。
2. main 套用無 bypass 的 active ruleset，要求 PR、必要 CI 指定來源、正確 Reviewer 核准、舊核准失效、最後推送者之外的核准、解決對話、禁止非快轉與刪除。在隔離保護分支測試否定案例，再實測正式規則。治理變更由 Owner 授權。
3. Program 使用限定 Repository、無 admin 權限的身分。Reviewer 採獨立 GitHub App 候選，唯讀驗證在隔離環境執行。核准能力所需的 PR 寫入權限只授與隔離憑證邊界。必須實測 App 的原生 APPROVED 能否計入必要審查。Program Session 不得取得 App 憑證或既有管理憑證。若 App 核准無法計入，回到治理選擇獨立具 write 權限的專用 GitHub 帳號，或另行核准綁定 App 來源的等效必要檢查。
4. 本機可執行整合 gate 讀取 GitHub 的 PR、狀態、審查與 SHA，缺資料即拒絕。Merge 呼叫附上已核准 head SHA；平台規則在實際操作時再檢查。核准前先確認治理決策及阻擋 findings。CI 與 gate 定義變更由獨立角色審查。

## 替代方案與成本

| 方案 | 隔離、成本與限制 |
| --- | --- |
| 獨立 GitHub App | 權限可限 Repository 與操作，以短期安裝憑證運作。需要配置隔離密鑰、驗證原生核准是否計入及憑證執行邊界。 |
| 獨立專用帳號 | 原生審查可用性較直接。往往須授與較廣的 Repository write 權，需管理獨立登入及憑證生命週期。 |
| 共用帳號搭配 GitHub CLI | CLI 可簡化操作。共用管理身分無法滿足角色隔離；改用工具本身也不改變身分。 |
| 只用 Actions 的 Github Token | 成本低。可經設定取得較高權限，但同一 PR 控制的 Workflow 與審查身分需另設信任邊界。現有候選不足以單獨作為獨立核准。 |
| 外部自建 CI | 控制較多，需要額外環境與維護，且新增外部服務與權限。 |

核准範圍預期涵蓋 hosted runner、main ruleset 與獨立身分方向。實際帳號、App 安裝範圍、憑證保管、是否使用付費服務及替代機制須另以可核對證據確認。若只核准 CI 或規則，先跑草稿 PR 驗證並保持未整合。

## 身分授權決議

負責人核准私有 Reviewer GitHub App 及獨立非管理員 Program 帳號。安裝限 AI-DevKit。Reviewer App 初期驗收使用 Contents read、Pull requests write 及 Checks write。Actions write 只在需要發起 hosted 重跑時使用。測試程序與 App 憑證分開，Program 使用獨立的非管理員登入及執行邊界。核准方向已確認，實際帳號、App 安裝及隔離環境仍待定位及驗證。

取得獨立環境後，由治理角色完成受控 GitHub App 註冊及限定安裝，憑證只送到隔離保管環境。Program 身分須查驗 Repository push 權及 admin 為 false，並證明無法存取管理帳號 GCM 與 Reviewer 憑證。先以隔離 PR 驗證 App 的原生核准計數與 Checks 來源，才綁定正式 main。禁止在對話、程式碼、正式工作目錄或 Program 環境交付憑證。
