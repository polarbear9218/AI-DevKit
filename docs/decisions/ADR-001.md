# ADR-001 初期架構與工具鏈

狀態：Accepted（有條件核准）。核准 Python 3.12 CLI、JSON Feature Map、Markdown 知識、unittest、Ruff、mypy、Gitleaks、Codex、獨立 Program／Review Session、本機整合及核心責任劃分。包含必要的安裝、設定、釘選及驗證。標準函式庫是初期選擇，後續替代方案依研究與治理流程評估。未列工具、服務、費用和權限擴張仍依治理決策。實際工具證據與限制見驗證紀錄。

## 推薦方案

採本機 Python 3.12 CLI，程式核心管理 Feature Map、政策與結構化結果，CLI 組合核心與 Git、測試器、靜態工具等外部介面。核心依賴標準函式庫。Feature Map 採每項功能一份 JSON 記錄，配合精簡索引及繁中 Markdown 知識；跨檔引用、路徑範圍及依賴圖以程式驗證。使用 unittest 驗證真實檔案與 CLI 行為。建議核准 Ruff、mypy 與 Gitleaks 作為本機開發工具，分別負責格式與 lint、靜態型別、秘密掃描。用 Python tokenize、AST 與專案驗證器處理註解例外、未授權抑制、模組依賴及工程知識引用。

Codex 提供探索及實作的 Harness。Review 採獨立唯讀 Session，輸入明確 Git base、target、需求與證據，產出結構化 finding。版本整合入口核對目標 SHA 與可驗證 gate；初期採本機流程。觀測、介入與改善使用精簡結構化紀錄。Software Verification 測程式行為；Agent Evals 另保存任務案例、可重跑判定與實際 Session 結果。後續以真實的 Athena Pilot 證據判斷是否需要擴充介面。

## 替代方案及成本

| 方案 | 主要利弊 |
| --- | --- |
| Python 加成熟本機工具 | 現有執行環境可用，專案專屬規則用語法分析；需管理工具版本與 Gitleaks 二進位散布。 |
| Python 全部自行實作 | 設定步驟較少；自行重寫格式、型別及掃描能力會增加維護成本與漏檢風險。 |
| Node.js／TypeScript | 已有 Node.js，可評估 TypeScript 與 ESLint；需另核准工具，相依鏈及工具安裝須驗證。 |
| Shell 與 Git 組合 | 適合薄操作層；跨平台路徑、結構驗證及可測試診斷的維護成本較高。 |

若工具組合未獲核准，可在重大架構獲核准後先使用 Python 內建能力實作可驗證的專案規則，格式、完整靜態型別與秘密掃描缺口依實際狀態保留。

## 事實、推論與待驗證事項

- Ruff 提供格式及 lint，採 MIT 授權。[官方專案](https://github.com/astral-sh/ruff)
- mypy 支援 strict 模式並採 MIT 授權。[官方入門](https://mypy.readthedocs.io/en/stable/getting_started.html) [官方專案](https://github.com/python/mypy)
- Gitleaks 提供本機掃描，專案採 MIT 授權。[官方專案](https://github.com/gitleaks/gitleaks)
- Codex CLI 官方文件列出非互動模式、唯讀執行及 JSON 事件能力。此處只確認本機可取得 CLI 版本。[官方命令參考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- 根據需求及本機工具盤點，推論 Python 與本機工具可提供低耦合、低基礎設施成本的初期方案。仍須驗證釘選版本在 Windows 可安裝、工具在唯讀審查環境可執行、掃描輸出已遮罩、Session 隔離及證據追溯有效。
- Review 優先沿用既有授權的 Codex Runtime。若執行要求新的資料傳輸、付費或權限，須取得對應治理核准。
